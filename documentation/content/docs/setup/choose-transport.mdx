title: Choose how mail leaves
description: Managed Postfix on your VPS, or an SMTP server you already have. Same API either way.
---

An installation sends through exactly one **active** delivery profile. The application API is identical for both, so you can change later without changing your code.

| | Managed Postfix | Existing SMTP |
|---|---|---|
| Good when | You have a VPS you control and want Njiwa-Mail to run the mail service | You already run, or rent, an SMTP server |
| You need | Debian 12 or Ubuntu 22.04/24.04 with systemd, a public static IPv4, reverse DNS you can set, outbound port 25 open, no other mail server on the host | SMTP host, port 587 (STARTTLS) or 465 (TLS), a dedicated submission account |
| Njiwa-Mail does | Configures Postfix and OpenDKIM with a reviewed, reversible installer; signs mail; relays bounces back | Submits to your server; nothing on that server is changed |
| DKIM and SPF | Generated and shown ready to publish | Your server's operator documents them; you enter them so they are checked |
| Optional extras | A mail queue screen driven by a small host agent | Mailcow API helpers, only if you choose Mailcow |

<Callout title="Not sure?">
Existing SMTP is the quickest start. Managed Postfix is for when you want full control and can meet its host requirements. A host that already runs another mail server, or Mailcow, is refused by the managed installer on purpose.
</Callout>

## Switching

Switching is planned and gated in the dashboard: unknown messages block it, pending jobs need an explicit choice, and the previous profile is kept so you can roll back.
