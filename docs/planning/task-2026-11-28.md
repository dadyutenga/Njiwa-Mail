## 1. Delivery infrastructure shows "Out of date (2/4)" at random (P0)

**Symptom:** the page says "Out of date (2/4). Mail delivery settings changed or were last checked too long ago. Live mail may not go out
until they are checked again", even though mail has been flowing for days.

**Cause found in code:** `internal/installation/installation.go`: `DefaultCheckTTL = 24 * time.Hour`. A check result expires 24 h after it was
run, and `checkStep()` then reports `Stale` / `CHECK_STALE`. Nothing re-runs the checks, so every install goes stale once a day unless
someone presses "Run checks again". Staleness also appears when `c.Revision != f.ProfileRevision` (a settings save bumped the revision).

- [x] **T1.1** Add a scheduler job `installation-recheck` (register it in `internal/cli/cli.go` next to the other jobs so it shows on the Platform
  page) that re-runs the active profile's connection checks before they expire (e.g. every 6 h, and always right after a profile or
  settings save). Reuse the existing test code; never send a real message from it.
  **Done (2026-11-28):** job `installation-recheck` (every minute, runs when due: 6 h, after a settings change, 10 min after a failure); reuses the profile test; sends nothing. `TestRecheckRefreshesTheConnectionCheck`.
- [x] **T1.2** Stop treating age alone as a failure. A check that is past its TTL **but** has fresh evidence (a Live message handed over and
  accepted by the mail server in the last N hours, from `delivery_events` / the last hand-over time) is shown as `Ready` with the line
  "Confirmed by live mail handed over at <time>". Only show `Stale` when there is no recent evidence either.
  **Done:** evidence is bound to the profile revision; the managed preflight needs a recipient server's acceptance, not only the local hand-over. Environment SMTP is attributed when identical to the profile. `TestOldCheckIsConfirmedByLiveMail`, `TestSettingsChangeIsStaleUntilTheNewSettingsAreShownWorking`, `TestPreflightNeedsRemoteAcceptance`, `TestEnvironmentSMTPIsAttributedOnlyWhenIdentical`.
- [x] **T1.3** Show **rejections by the mail server** as first-class evidence. When the server answers a submission with a 4xx/5xx
  (auth failed, relay denied, sender rejected, recipient rejected, policy/spam, rate limit), store the reply code and a short safe
  reason on the message and in `delivery_events`, surface it in the message timeline and the delivery health card, and map it to a
  problem code with a fix. Repeated connection-level rejection moves readiness to `degraded` (the circuit breaker already exists, reuse it).
  A 5xx for one recipient must not mark the whole installation unhealthy.
  **Done:** migration `0042`; shown in the message timeline, delivery evidence, the delivery page and the dashboard health card. `TestClassifyRejection`, `TestRefusalReasonIsSafe`, `TestRefusalsAreRecordedAndOneBadRecipientDoesNotDegrade`, `TestRepeatedSignInRefusalDegradesReadiness`, `TestBreakerCountsRefusalsThatStopEveryMessage`.
- [x] **T1.4** Make the UI explain itself: each stale step names *why* ("settings changed at 14:02" or "last checked 31 h ago, no live mail since"),
  shows a **Run checks again** button, and the dashboard banner does not say "Live mail may not go out" when live mail demonstrably went out.
  **Done, with one difference:** a stale connection step has **Run checks again**; the stale test-message step links to the test form instead (the automatic check never sends mail), and the preflight step shows its host command (item 9 automates it). `Evidence.test.tsx`.
- [x] **T1.5** Tests: a check older than the TTL with recent live evidence stays Ready; with no evidence it is Stale; the scheduler job
  refreshes a check before expiry; a 550/554 reply is recorded and shown; a single bad recipient does not degrade readiness.
  **Done:** tests above.
- **Joint test:** leave the stack running 48 h with the scheduler on; the card must not go "Out of date" without a real reason.

`role='relay'` newer than 1 minute (`internal/service/relaystatus.go`).

  Write the root cause in the commit message.
  **Done (2026-11-28), from the code and a local Compose run; the production server was not inspected.** Causes: the deploy script never started the `relay` profile; without a readable certificate the process exited in a loop (after possibly recording one heartbeat); the API reported its own default port 587 and a placeholder host.
